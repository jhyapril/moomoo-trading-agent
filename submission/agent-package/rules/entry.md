# 入场流程

每次运行按顺序执行。某项失败只终止该标的本次评估，不终止当天。

## Gate 0 — 环境

1. Moomoo 鉴权有效；绑定的工具能响应一次只读调用。
2. 解析出的账户与 `config.yaml` 一致：`account_id`、`market_id`、
   `account_type == 2`、title 含比赛标记。任一不符即整场硬停，立即报告。
3. 所交易市场处于 open/trading。盘前或收盘意味着不开新仓；已有持仓的出场照常执行。

## Gate 1 — 状态对账

1. 从券商读取持仓与现金。
2. 读取上一个 journal 记录。
3. 任何差异必须在下单前完成对账，以券商状态为准。无论是否一致都要记录差异。

## Gate 2 — 风控容量

全部来自 `rules/risk.md`。如果容量为零，停止；不得"缩小"一条规则来迁就交易。

## Gate 3 — 信号

股票走两段：盘中全量判定资格并试探，次日确认。

1. **数据新鲜** — 时间戳在当前会话内，无过期或空字段。缺失值绝不默认成零。
2. **盘中资格（每次运行）** — 按 `cadence.poll_interval_minutes` 对 `universe.symbols` 全部标的，
   用已收盘日线缓存 + 实时价运行 `src/watch.py`，按 `STRATEGY.md` §4.1 判定；不再要求前一日
   收盘已入选计划。
3. **试探触发（盘中）** — 按 §4.2："站稳 2 小时"或"+2% 冲高"之一成立。试探仓不要求量比。
   突破晚于 `entry.late_breakout_after` 时，按 §4.4 只走冲高或收盘确认。
4. **确认加仓（次日）** — 在 `entry.confirm_eval_at` 按 §4.3：仍在突破位上方、趋势/RSI/%B/
   财报成立且量比达标，才补 `entry.confirm_ratio`；否则不加，转出场流程。
5. **成本** — 按 `backtest/cost-model.md` 的公式，用实时盘口点差 + `cost` 块费率 + 滑点、
   以该笔拟下单股数算往返成本；`exits.stock.take_profit_pct` 须 ≥
   `cost.min_edge_cost_multiple` × 往返成本。盘口缺失/过期/买卖一为空 → 不通过。
   期权 sleeve 在成本模型补齐前一律不通过。

试探仓与确认加仓各自独立通过 Gate 0–2 的全部容量检查，各自有去重键。

## Gate 4 — 记录意图

发单前先写入 journal：

- 标的、方向、数量、订单类型、限价或限价区间
- 触发的规则及背后数值（`probe` 或 `confirm_add`，突破位、触发路径、计划股数）
- 预期出场与止损
- 由 (日期, 标的, 规则, 方向) 派生的去重键

若同一去重键已存在且已成交或在挂，跳过。`probe` 与 `confirm_add` 是两个键，互不覆盖。

## 禁止

- 永不突破 `max_position_pct` 补仓摊薄。
- 永不在确认条件不成立时"先买了再说"。
- 永不开仓不在 `universe.symbols` 里的标的。
- 永远不要为了"agent 该做点什么"而下单。
