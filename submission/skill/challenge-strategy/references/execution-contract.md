# 执行契约

无论订单走 MCP 工具还是 CLI，本契约都适用。

## 幂等

- 去重键：`date|symbol|rule_id|direction`。
- 发单**之前**先把意图写入 journal。
- 启动时从 journal 重建存活键；已成交或在挂的键跳过。
- 重跑一次会话必须安全：至少一次提交，状态迁移幂等。
- 模拟下单接口**没有客户端订单号**。发单前必须查当日订单列表，按（symbol、side、qty、price）
  与 journal 意图匹配；命中即视为已发，不得重发。重启后的去重只能依赖这一步。

## 对账

1. 券商是事实；本地状态是缓存。
2. 将持仓、现金、在挂订单与上一条 journal 记录比对。
3. 不一致时：采纳券商状态、撤销不明在挂订单、两边事实都记入 journal。
4. 永远不要用补偿性下单来"修复"不一致，除非该意图本身也先写入 journal。

## 订单卫生

- 优先限价单；必须成交的出场用可成交限价。
- 一次一个标的；确认成交或在挂状态后再进行下一个动作。
- 运行结束时撤销过期在挂订单。
- 记录滑点：每张订单的成交价 vs 意图价。

## 失败处理

| 失败 | 动作 |
|---|---|
| 提交超时 | 先读订单状态再重试；仅在订单不存在时重试 |
| 部分成交 | 记入 journal；本次运行不补发剩余数量 |
| 订单被拒 | 记录原因码；不重发同一报文 |
| 账户状态不明 | 停止、报告、不猜测 |

## Team 执行边界

- 执行协调者是唯一券商写入者，也是交易 journal、次日计划与历史行情缓存的唯一写入者。
  数据、风控退出成员只返回结果，不写共享文件；所有成员都不调用下单、改单、撤单或交易 CLI。
  数据员可只读本地历史日线 JSON 并返回新增原始行情；协调者按作战手册校验、合并缓存。
  协调者每轮无条件把数据员快照原子存档到 `shadow.snapshot_dir`（先写临时文件再改名），这是交给
  影子交易员的唯一通道；协调者不调用影子交易员，不等待它。影子交易员在自己的定时任务里异步读取、
  自行读取缓存与行情、只写 `shadow/` 下自己的虚拟账本与笔记，零真实订单、不读比赛账户。
  每轮对账发现任何无法对应 journal 意图的订单，即停止入场并报告“未知来源订单”。
  协调者与影子交易员提交时都用 `git commit -- <自己的路径>`，互不带入对方暂存的文件。
- 每轮分配 `run_id`；交接含 `snapshot_id`、行情时间、账户/订单快照、策略/config 指纹与缺失项。
  无同轮、同版本、有效快照的风控审核，不得入场；发单前仍须重新读取券商状态并逐项过门控。
- 风控成员可否决入场，不能否决符合现行规则的减风险出场。风控成员失联时，协调者自行按
  既有规则检查出场并禁止新仓；数据和研究工作不得阻塞止损。研究成员不能签发交易批准。
- 未确认唯一启用的交易入口、跨会话互斥、账户身份及对账链路之前，Team 仅做只读验证，
  不得与原盘中任务并行发单。跨轮结果不得被当作当轮批准；重叠运行或身份不明即停止入场。
- 成员超时、缺数据或返回冲突时记录缺失，不递归创建团队，不为了交差补交易。
- 盘后更新全部标的已收盘日线缓存、存档分钟线、记录次日突破位与比赛账户对照数据；影子交易员在自己的复盘任务里复盘虚拟账本。不发订单，不把研究结论直接写回 config。

## 密钥

任何 token、cookie 或凭据都不得出现在 journal、日志、代码或输出中。OAuth 由客户端附加；
agent 永不接触。
