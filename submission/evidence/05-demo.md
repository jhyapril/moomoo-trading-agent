## 1. 有效的部分

### 1.1 fail-closed 财报门：把 13/14 只标的挡在门外，并且知道为什么挡

`signal.earnings_blackout_days = 3`，且**查不到财报日同样不进**。11/25 收盘任务对 14 只逐只穷举
`quote_financials_earnings_price_history`（实测 53–57 万字符/只，整段落盘后脚本解析，无手抄），
只接受 `is_current = true` **且** `pub_trading_day > T` 的前瞻行。结果：

- 仅 **AVGO（2026-12-09 19:30 ET，距 N 12 天）** `earnings_ok = true`，其余 13 只 false；
- NVDA 有 21 条 `is_current=true` 但**全部落在已披露的过去日** ⇒ 那是"最新记录指针"不是未来排期，判 false；
- MU 有 14 条未来行但**整批缺 `is_current` 字段** ⇒ 不满足接受标准，按未知处理，false。

关键在于这条规则**没有把"查不到"当成"没有财报"**。这 13 只的 false 是"无采信证据"，
不是"已证明不在窗口内"——这个区分被明确写进 11/27 的表头。11/23 CRWD 在开盘当天被实际披露替换
的先例，就是这条区分存在的原因：预写表只能作盘中默认值，**绝不能作入场的唯一依据**。

### 1.2 硬止损被执行成一条纪律，而不是一个情绪

11/19 NVDA：止损线 147.345。从 12:06 ET 起 **8 轮连续记录**逼近（当日 low 147.82 同时是 52 周低，
距止损 +0.4% → +0.8% → +2.0% → +2.0% → +1.3% → +1.5% → +1.0% → +0.76%），**每一轮都 HOLD、
出场订单 0**，没有提前跑；14:58:24 买一 147.25 真正越线才动——先写意图（14:58:30）、再发单
（14:58:39）、全部成交（14:58:42）10 股 @147.28，去重键 `2026-11-19|US.NVDA|stop|short` 防重复，
一次全量而非部分出场。成交价较限价 +0.03，滑点在有利方向。券商侧无条件止损单
（`sim_trade_input_order` 仅限价/市价），这一点在 12:06 就被登记为约束并据此设计执行方式。

### 1.3 量比门拦下了"已经突破"的标的

11/17 补扫 30 只全覆盖：**0 只通过全部技术门控**。最接近的两只其实**已经在突破位上方**：

| 标的 | 距前 20 日高 | RSI | %B | 量比 | 结果 |
|---|---|---|---|---|---|
| KO | **+0.18%** | 74.1 | 0.978 | 1.05 | ✗ 量比 < 1.2 |
| APP | **+1.34%** | 73.7 | 0.863 | 0.79 | ✗ 量比 < 1.2 |

"量能不足即不追"是用户实盘标准的原样落地。同一天 30 只里 **28 只收盘低于 MA50**，SPY/QQQ 均在
MA50 下方且 MA20 < MA50——**普跌，不是个股噪声**。这套门控在错误的市场里正确地什么都没做。

### 1.4 判定面是程序产物，不是人工汇总

`src/watch.py` 每轮把 14 只的 15 列判定追加进 `watch.csv`。比赛期间共 **1,260 行 symbol-evaluation**：

```
qualified=True  :    0
trigger 非空     :    0
gap_pct > 0     :    0 / 1260      ← 没有一次现价越过 20 日突破位
被拦下的门：price>breakout 1246 (98.89%) · earnings 1073 (85.16%) · price>ma_slow 863 (68.49%)
             · ma_fast>ma_slow 717 (56.90%) · missing_live_price 14 (1.11%)
每日最近：11/19 AVGO −0.57% · 11/20 KO −2.84% · 11/23 AAPL −2.49% · 11/25 AAPL −1.65%
```

突破位由 `watch.py` 与负责人自算 20 日高**双实现交叉验证，14/14 完全相同**。
这 1,260 行就是"AI 每天盯盘 72 次却不下单"的可审计证明——不是空口说的谨慎。

### 1.5 新鲜度门宁愿关掉自己的触发面，也不用过期价入场

11/25 R2：成员 10:42 下发、11:16 才取数（34 分钟），返回后 11:50 才判定。数据龄 > `poll_interval 600` 秒
⇒ **判定"本轮新鲜度 FAIL、触发面关闭"**，并在同一轮里对 7 只做了只读复核确认仍 0/7 越位、
**明示该复核不是入场依据**。R5 批次龄实测 1,025.6–1,036.6 秒同样 FAIL。
**一个会在自己数据不新鲜时主动弃权的市场判定器，比一个总能给出买入答案的更有价值。**

### 1.6 对账：券商是事实，成员不是写入者

每轮在下发成员前/后、以及运行结束时各查一次订单集。11/25 收盘任务四向 0 差异：
订单集恒等于 `{3254277, 3249625, 3246054, 3246050}`、`has_more=false`、
**0 笔未知来源订单**。持仓恒为 `[]`。这条纪律是为了防"旧单 Agent 任务与 Team 同时发单"这个具体风险。

### 1.7 影子账本的自我约束

- SYSTEM 权益差与"已实现 + 未实现 − 费用"闭合到 **0.01 美元**（24 本、136 笔）。
- **补记率 39.71%（54/136）**，且按日拆开看是 11/19 0、11/20 0、11/23 0、11/24 8、**11/25 46（46/46 全补记）**——
  这个数字被主动公开，并直接导致当日**前瞻样本 = 0**，因此 11/25 的**所有研究建议被封顶在
  「继续观察 / 建议验证」，没有一条升到「保留」**。
- 亏损、放弃的账本和未成交照样保留：`shrt10 −14.899%` 排在表首，最差的一本没有被删掉。
- 11/25 收盘出场审计里，9 笔 AVGO 一律按"首次可观察越线"的 299.77 买回，而这个价格是越线后
  **最便宜**的一个收盘读数——这条"选它是对自己有利的读数"被主动披露，而不是藏起来。

### 1.8 工程底座

36 个单元测试（19 缓存 / 9 影子 / 6 门控 / 2 锁）全部通过，stdlib-only、无第三方依赖，
Python 3.9.6 直接跑。日线缓存 14/14 `valid=true`、373 根；分钟档案 14 只 × 5 日、
每只 390 根、missing 0、duplicate 0、close 与日线缓存 14/14 相等。

## 2. 失败的部分

### 2.1 `run_lock.py` 缺 `renew`——同一个缺陷登记了 14 次，一直没修

实测 `src/run_lock.py` 只有 `acquire` / `release` 两个子命令。后果是任何长轮次必然让锁龄突破
`stale_seconds 900`：

| 轮次 | 持锁 | 倍数 | 实际后果 |
|---|---|---|---|
| 11/25 R5 | 87.35 分钟 | 8.73× poll_interval 10 | 越过 `entry_window` 15:30 终点，**15:25 `confirm_eval_at` 唤醒被自己的锁挤掉** |
| 11/25 收盘任务 | 109.2 分钟 | 7.28× stale 900 | 跨过 11/25 收盘后全段（入场窗早已越过，代价 0） |
| 11/25 R3 | 3,052.5 秒 | 3.39× stale 900 | — |

当日入场机会代价为 0 是因为**根本没有 probe 存量**——这是运气兑付的流程失败，不是流程成功。
journal 里明确写了这句定性。**这是一个已知、已登记、已承诺整改、但连续 14 次复现未修的缺口。**

### 2.2 瓶颈会搬家，每次都归因错了地方

- R1：判定 09:53 完成，存档脚本 10:11 才跑 ⇒ 一轮 10 分钟节拍的墙钟拖到 **36.7 分钟**。
- R2：归因"成员往返 34 分钟"。**R3 把成员往返压到 4.1 分钟后，瓶颈立刻转移到负责人自己的
  journal/提交路径**（判定后仍占 52.6 分钟）。
- R4 承诺"判定后 5 分钟内完成主提交"，**R5 彻底没守住**（判定→提交约 37 分钟），
  这次返工直接吃掉了触发面。
- 收盘任务：全程持锁 109.2 分钟，根因是大响应 + 中途上下文压缩 35.2 分钟（期间零券商调用、零写入）。

**教训：把延迟归因给"下一环节"是幻觉，必须分段计时。** R5 起 journal 里开始写分段耗时表，
这才第一次看清瓶颈在哪一侧。

### 2.3 时间戳造假（我自己造的，两次，同一类错误）

1. **R5**：第一版存档用"写存档的时刻"当判定时刻，把数据龄报成 1,045 秒；后按 `watch.csv` 的
   mtime 还原真实判定 15:01:26 ⇒ 更正为 1,025.6–1,036.6 秒。
2. **收盘任务**：`archive_minute.py` 把 `fetched_at_utc` 与 `written_at_utc` 写成同一时刻 =
   **用写档时刻冒充取档时刻**。三只标的实际滞后 2,110 秒（响应早已到达，卡在
   "响应已到 → 上下文压缩 → 恢复落盘"这条路径上）。已按 harness 落盘 mtime 逐只回填
   `raw_response_arrived_at_et` / `archive_lag_seconds`（实测 29.8…2,124.7 秒），**原字段不回改**。

这类错误对研究数据是致命的——事后回填的时间戳无法区分"我看到了但没动"和"我根本没看到"。
整改（写档时刻由脚本自取 mtime、判定与存档同进程）到 11/25 收盘任务**仍未完全闭环**。

### 2.4 10 分钟轮询在止损侧的真实价格：11/25 一天 3,691.15 美元

`cadence.poll_interval_minutes = 10`，而当日实际快照间隔 **17–73 分钟**。第一次可量化的止损滑价：

| 批次 | 标的 | 成交 − 线 | 多付 |
|---|---|---|---|
| 14:44 | MU | +1.219% | 9 本合计 |
| 14:44 | AMD | +2.048% | **3,011.49 USD**（摊到各本 −0.9%…−1.6% 权益） |
| 14:44 | CRWD | +0.076% | — |
| 15:56 收盘 | AVGO | +0.378%（+1.129/股） | **679.66 USD**（602 股） |

**同一 cadence 下这条对现行 §5 的多头止损同样成立，只是方向相反。**
建议的形式是把止损判定与入场轮询解耦（由 close 侧独立高频跑），而**不是**去调
`poll_interval_minutes` 这个入场侧旋钮——调它会把入场采样一起放大，成本结构不可归因。
样本仅 2 批、0 笔前瞻样本 ⇒ **级别封顶在"建议验证"**。

### 2.5 判据文本缺陷：`shrt10t` 的移动止损捕获率恒等于 0

写法是"线 = 历史最高不利价 + 锁定距离"。对空头而言，任一 bar 的 high 恒 ≤ 历史最高不利价，
**这条线在数学上不可能被越**。11/25 三条旧线（AMD 426.6545 / MU 634.5700 / AVGO 315.4910）
全天 **0 次被越**，而 15:56 的 299.77 距其 AVGO 线 −4.98%；同一批 9 本固定止损全部打穿。
本本三腿 0 笔出场，浮动 −2,958.85 对 `shrt10` 已实现 −14,014.89。

这是**文本缺陷，不是市场结果**。定稿读法改为"建仓后最低可观察买一 + 锁定距离"，
但**当日三腿不回改**——事后挑一条对自己有利的线，比符号歧义本身更严重。新读法自 11/26 新腿生效。
同类问题第 2 例（第 1 例的歧义会吞掉整本账），规律是"**文本歧义只在第一笔暴露**"。

`shrt10nw10` 的死区带同样拿到第 2 个 0 效果样本：298.9396 阈值被 299.77 同时满足"越线 + 幅度"，
与 `shrt10nw` 同根同价、0.10% 一字未动 —— 该参数在当前市场里**没有可测量的作用**。

### 2.6 官方费用与现金流接口连续 3 日不可得

`account_order_fees` ×3、`account_cash_logs` ×2 全部 `-32603`。这是**工具失败，不是数据不存在**。
后果：真实费用只能用权益差反推 ≈1.99，`config.cost` 块的费率也从未对账单核实过。
`backtest/cost-model.md` 与 `config.yaml` 的注释都按此登记，不用模型值冒充账单值。

### 2.7 成员偏差与自己的清单错误

- 数据研究员曾列出**不在 universe 的 AMZN** 并漏掉 ISRG/TSM；声称"当日 1 分钟 kline 不可用"，
  而负责人用 `start=T / end=T+1` 14/14 取到 390 根。
- 风控成员自报 1 次只读 Bash `ls` 越出"仅只读 MCP"的边界。
- **负责人自己的错误**：11/20 给成员的复核清单误写 WMT/COIN（不在 universe）并漏 APP/AVGO/CRWD，
  成员照单如实报"无存档"；后果是那三份分钟档案**只经过写入时自校验，未经成员二次核验**，
  被登记为待抽查项。
- 这些偏差**不采纳、也不因此改动判据**，只登记。

### 2.8 从未跑过回测

`STRATEGY.md` §3 开赛前就写"回测区间：待验证（本次比赛窗口仅约 8 个交易日，未跑完整回测）、
样本量：待验证"，并规定"没回测就写待验证，不编数字；先在 `backtest/` 按 README 的标准验证，
通过了才开工交易"。这条纪律在 11/17 被执行了（那天 0 个入场意图，所以 0 笔交易不依赖回测结论），
但**"通过回测才交易"这个前置本身从未真正闭环**——`backtest/` 里落地的是单元与契约测试，
不是样本外收益验证。这一点必须在提交里说清楚，不能被前面那些纪律性证据盖过去。

## 3. 为什么真实结果是 0 笔入场

不是系统坏了，是**市场没有提供这套策略要求的东西**。三个门在 11/27 的交集为空：

| 门 | 状态 | 证据 |
|---|---|---|
| 突破门 | 14/14 未越位 | 11/25 无一只刷新 20 日高；1,260 行 `gap_pct > 0` = 0；最近 AAPL −1.65% |
| 趋势门 | 仅 5 只通过 | AAPL/KO/TSLA/ISRG/APP（ISRG 过的是 close>MA50 +0.86，而 close>MA20 是 −11.76） |
| 财报门 | 仅 AVGO 通过 | 而 AVGO 距突破 −18.6469%、趋势门 ✗、需再涨 +22.92% 才触线 |

趋势门 ∩ 量能门（`signal.volume_multiple 1.2`，不含 T 口径）交集只有 KO，而 **KO 财报门 false**。
11/25 全池仅 2 只收涨、12 只收跌（MU −4.5317%、NVDA −3.9130% 最深）——11 月第三个交易周的 risk-off 环境。

**最硬的一条对照**：同一天、同一批行情、同一个标的池，现行只做多 sleeve 0 候选 0 单、权益变动 0.00%，
而影子镜像做空族已实现 −13,577 … −14,015。
**空仓躲过的不是抽象的亏损，是那 3,011 美元止损滑价加 11,674 美元方向错误本身。**

## 4. 研究的产出与边界

盘后研究给出的建议全部带级别，且**没有任何一条被自动写进正式策略**：

| 建议 | 级别 | 依据 |
|---|---|---|
| 把止损判定与 `cadence.poll_interval_minutes` 解耦 | 建议验证 | 11/25 两次可量化滑价 3,691.15；0 笔前瞻样本 |
| 影子盘后轮改在分钟档案落盘后再启动 | 建议验证 | 46/46 补记的根因是档案晚到，非研究员慢 |
| `shrt10t` 文本缺陷升级为新读法（11/26 新腿生效） | 建议验证 | 捕获率恒 0 属结构性；当日三腿不回改 |
| 现行只做多 sleeve 保留 | 保留 | 0 违规、0 阈值改动；但**不得把空头族盈亏搬给多头侧记分** |

比赛窗口短，**几次成功或账本汇总都不算盈利验证**——这句话写在 `STRATEGY.md` §8，
也是 `shadow.py report()` 里那个 `evidence_limit` 字段的原文。
