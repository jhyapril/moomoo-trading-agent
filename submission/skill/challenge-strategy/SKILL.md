# 比赛策略

比赛账户的纯模拟执行。本 skill 是行为底线：若 `config.yaml` 与本 skill 冲突，取更严的规则。

## 硬限制

- 仅限模拟账户。要求 `account_type == 2`、`account_id` 与 `market_id` 匹配、title 含比赛
  标记。任一不符则整场会话停止。
- 永不调用实盘证券、加密或保证金交易接口。
- 永不读取、打印或持久化 token 文件；OAuth 由客户端附加。
- [风控上限](references/risk-limits.md) 在**发单之前**强制执行。检查失败时跳过该动作并把
  原因记入 journal——永远不要为了迁就交易而削减规则。
- 每个标的每次评估只做一个决策。不得突破仓位上限补仓摊薄。

## 运行顺序

1. **预检** — 确认绑定的 Moomoo 工具能响应只读调用，解析账户，核实市场状态。休市或盘前
   不开新仓；出场照常执行。
2. **对账** — 读取持仓、现金和在挂订单，与上一条 journal 记录比对。券商状态是事实。
   任何差异都记入 journal。
3. **出场优先** — 先按[作战手册](references/playbook.md)评估全部持仓，再考虑入场。出场永不
   因风控容量被阻塞。
4. **入场** — 按顺序评估各道门控；股票走"盘中全量资格 → 试探仓 → 次日确认加仓"两段，两笔
   各自记录意图、各自去重，去重键为 `date|symbol|rule|direction`。该键已成交或在挂则跳过。
5. **Journal** — 追加到当日记录：决策、订单、成交、盈亏，以及任何规则违规。没有 journal
   记录的一次运行等于没有发生。

## 四角色 Team（接入前只读验证）

| 角色 | 权限与输出 |
|---|---|
| 数据研究员 | 只读行情/新闻及本地历史日线缓存；返回新增原始行情、同轮候选、来源时间、指标、财报与缺失项 |
| 风控退出审核员 | 只读比赛账户；逐项审查风险、优先提出出场，拥有入场否决权 |
| 执行协调者（负责人） | 唯一发单及共享文件写入入口；实时复核、先退出后入场、对账和日志 |
| 影子策略研究员 | 独立的影子交易员，跑自己的定时任务：异步读取快照、缓存与行情，在 `shadow/` 自建多个虚拟账本，用假设成交试各种策略并盘后对比复盘；零真实订单，不改正式策略 |

先验证四个角色的配置已保存、团队可用及工具限制生效；未完成时不把现有定时任务切到 Team。
实际交易接入须满足[执行契约](references/execution-contract.md)的独占入口要求；首轮只读，
不得以团队已创建或任务已受理代替账户、风控与发单链路验证。研究记录遵循
[作战手册](references/playbook.md)的影子研究契约，影子交易员自行写 `shadow/`；研究不得拖延出场。

## 工具选择

使用环境中绑定的任一 Moomoo 接口——MCP 模拟交易工具或 `moomoo sim` CLI。命令与参数细节
属于 `moomoo-sim-trading` skill；不得自创参数。若未绑定任何模拟交易接口，停止并报告能力
缺失，不得回退到其他工具。

## 停止条件

出现以下任一情况即停止运行并报告：鉴权或权限失败、账户不匹配、数据过期、当日亏损上限、
回撤上限，或记录到三次规则违规。回撤停用后的恢复由人决定，不由 agent 自主决定。
